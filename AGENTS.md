# Project conventions

Use Northstar Telecom as the fictional operator everywhere, including data and exports. Do not add real operator names or internal network information.

Focus the first lab on hosted Jev, a local trained ML classifier and a transparent rules reference. Do not download language-model weights or introduce other model providers without a new request.

Keep input packets and answer keys separate. Original Jev/ML share the original allowlisted state string; focused Jev/revised ML share the compact allowlisted state string. Fit ML features and classifiers only on the training split. Do not tune against test or challenge labels.

Show actual predictions separately from reference decisions. Never fill missing model results with fabricated scores. Label synthetic results and keep them distinct from operational evidence.

API keys remain server-side, out of Git, logs and exported results. The app binds to loopback. Nothing in the lab executes network changes.

Run dataset validation, the unit suite and JavaScript syntax checks after changes to inference or evaluation. Update the learning guide when the workflow changes.

Use the app labels Rules, ML · original, ML · revised, Jev · original and Jev · focused in guides. Keep the user-edited experiment overview and exported Markdown copies aligned. Preserve frozen data and measured results; raw runs and credentials stay ignored. Run the Python suite, dataset validator, all three browser-script syntax checks and `node --test tests/explorer-ui.test.cjs` before publishing changes.

Write study narration in first person for authorship, choices, judgments and limitations. Let models, data, methods and results lead descriptions of their behavior. Avoid repeated “I used,” “I trained” or “I will” openings. Preserve completed-versus-planned work and technical qualifications when revising prose.

Keep HANDOFF.md and the historical bundle guide aligned with the study. Historical evidence is a versioned release asset, not tracked run files. Never overwrite an existing run or replace a released bundle with different evidence.

Experiment 3 lives in `triage_bench/experiment3/` and a separate draft data directory. Preserve historical inference and data. Its four ML arms share training packets and settings; only input facts vary. Keep references provisional and Jev explicitly unrun until recorded hosted responses exist. Do not generalize draft development scores into historical deltas or operational claims. Include `experiment3.js` in syntax checks and run the new pack validator.

The separate question-precedence trial uses `data/experiment-3-question-draft/` and `question_trial.py`. Both Jev arms receive identical combined states; only three question instructions change. Preserve recorded trial source and requests. The user selected NOC retention until current evidence links a fault to affected service as a synthetic teaching rule; this does not establish specialist review. Include the question-pack validator in checks and keep field-level regressions visible alongside aggregate gains.

The conflict repetition pack reuses frozen question-trial requests on further development pairs. Preserve `conflict_trial.py` and its recorded source fingerprints after inference. Score each repetition separately, and distinguish eight distinct packets from repeated response counts. Include its validator in checks. Next input revisions need further development families; do not tune the recorded conflict pack or claim stable wrong answers are reliable.

The evidence-selection trial keeps candidate_questions() frozen and uses new families in `data/experiment-3-selection-draft/`. Eligibility uses only currentness and visible dependency paths; never derive a domain or reference answer in the calculator. Preserve `selection.py`, `selection_data.py` and `selection_trial.py` after inference. Retained rows must join by their new observation_index and preserve source_observation_index. Keep raw reports inspectable outside filtered requests, include current-conflict and empty-evidence controls, and run the selection validator.

The selection-robustness check adds eight packets in four further families, with two frozen inputs repeated three times. Preserve robustness_data.py, robustness_inference.py and robustness_trial.py after inference, along with their data, recorded requests and source fingerprints. Include its validator in checks. The multiple-domain NOC reference is a provisional interpretation of the frozen no-unique-domain clause, not specialist signoff. Report one distinct boundary fix separately from three repeated responses. Keep Jev and selection frozen for the next structured-feature ML comparison; use separate new development families and matched training settings.

The structured ML comparison uses separate training/development families in data/experiment-3-structured-ml-draft. Preserve structured_data.py, structured_features.py and structured_ml.py after fitting. All arms share train-only vocabularies, impact-only priority and the same logistic settings. Input-only categories bind observation text to channels; retain all reports and never calculate a fault domain or reference answer in features. Score complete-packet and field regressions separately, including newly wrong fields on already-failed packets. Save and verify vectors and fitted score margins. Include the structured-pack validator in checks. Wording counterbalancing needs a separate development study; do not tune or rewrite recorded inputs or labels.

The training-wording study preserves wording_data.py, wording_ml.py and data/experiment-3-wording-draft after fitting. Matched coupled/counterbalanced inputs differ only in method nouns; targets and all non-text evidence are unchanged. Original training is a bridge control. Development inputs match across arms, with separately fitted train-only vocabularies. Report negative matched results and stable wrong synonym pairs. Include its validator. The next observation-interpretation study needs new families and separate annotations; never infer observation targets from packet decision keys or disguise fault classification as an input-only calculator.

The report-policy study preserves interpretation_data.py, interpretation_model.py, interpretation_trial.py and data/experiment-3-interpretation-draft after inference. Report domain/reading annotations are written separately from packet references. Interpreters see only normalized report text; fixed policy joins predicted meanings to input-only currentness, paths and asset grouping. This is an architecture/supervision comparison, not a feature-only ablation. Reference-reading-fed policy checks remain evaluation diagnostics, never model scores. Include its validator and preserve report vectors, score margins, policy traces, matched regressions and wrong readings hidden by correct triage. Broader wording needs further development families and a separate matched training study; never retune the recorded pack.
